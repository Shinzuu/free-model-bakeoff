The short version

Small beats large

gpt-oss-20b scored 88% against its own six-times-larger sibling's 64%. The big one produced ten failed calls to the small one's two — most of them tool arguments that did not match the schema.

Provider ≠ model

The same weights on a different free host scored 64% at a 28-second median, and on three questions collapsed into 2048 tokens of !!!! — after calling the correct tool.

The real ceiling is daily

Not tokens per minute — tokens per day. 200,000 per model, documented nowhere except inside a 429. At our prompt size that is about 60 questions a day for everyone combined.

The best fix was a sentence

The prompt defined "overdue" but never defined "open". Adding one line took two questions from never correct to mostly correct — a bigger gain than the gap between any two models here.

Two experiments

Each changes exactly one thing against the same model's own baseline, on the same questions, so the difference is attributable. Both ran on the runner-up — the winner's daily budget was already spent, which is itself the finding.

1 · Send fewer tool schemas

All 17 tool schemas go to the model on every round trip. This arm narrows the list by intent with keyword matching before the call — deliberately not another model call, since a router that costs a round trip gives back what it saves.

2 · Define "open" in the prompt

Models counted only TODO as open and dropped IN_PROGRESS — sometimes in the same reply that had listed IN_PROGRESS correctly one clause earlier. The prompt defined "overdue" and never defined "open".

How this was measured

The real code path

The eval runs production's own tool loop, its 17 tool schemas and executors, and its system prompt read out of the source at run time so it cannot drift. Only the data layer is swapped: every tool already takes a small database interface, so a fixture implementation stands in for it. No database, no writes anywhere.

Hostile on purpose

A client and one of its projects share a name. One person's first name is another person's surname. A completed task sits past its due date and must not count as overdue. A shift is left open and a timer is still running.

Grading, and its price

Substring and regex against pinned ground truth — no model-as-judge, so any grader change can be re-scored against every stored reply for free. The price is that an unusually phrased correct answer can still fail, so failures are read, not trusted.

Six harness bugs first

Every early "bad model" result turned out to be our own: silent model substitution on a 404, models that cannot call tools at all, pacing sized per round trip instead of per question, and four graders that failed correct answers — one over a Unicode apostrophe. Read the reply before believing a low score.

What this page is not

  • Every person, client and project named here is invented. The recorded runs used internal names with the same structure; the names do not affect any measurement, the shapes do, and the shapes are unchanged.
  • The fixture database is small — about 5 people, 8 projects, 18 tasks. It measures routing and reading, not behaviour at production scale.
  • Two candidates were never evaluated: they exhausted their daily budgets before producing a usable sample. Nothing here is a judgement of them.
  • Both experiments ran on the runner-up, not the winner, for the same budget reason. Whether the deltas carry across is untested.
